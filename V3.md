# Training workflow — release 2026-10-30.16

## At class

Train → Class starts with no blocks. Add a lift / complex. Choose a base movement,
then its position, receiving, grip and technique. Add another movement for an
ordered complex; duplicate or reorder components. Each stage has sets, reps for
each component, and either percent or kilograms. The reference is the normal
movement, not a derived hang max. Override today's reference without changing a PB.
The title comes from session type and date.

Photo / paste reads a photo on the device using lazy-loaded Tesseract.js 5.1.1.
The first use needs internet to load the reader/language. The app does not upload
photos to a recognition API. Handwriting recognition is imperfect. Always review
the editable transcription and then the composed plan; nothing is logged by OCR.
Supported transcription: a movement heading followed by `sets x reps @ percent`,
with `+` between complex components and rep counts. Unrecognized movement names
remain editable Other movements. Accessories are optional session notes.

Start session → adjust actual weight/reps/notes → Complete set. Only completion
records a lift, using stable IDs and a durable retry queue. Actual fields are not
replaced while typing. Notes, coach cues and optional accessories are available
during and after lifting. Leave offers keep draft or discard unfinished plan;
completed sets remain. 1:1 offers logging afterwards or building a lesson plan.

Saved templates appear on Train home with Open / Delete. A template contains no
completed sets; opening makes a new dated session. Starting a new plan replaces
the current draft; the switch screen preserves it until another plan is selected.

## Loading and rest

Gym: 20kg bar, one pair of each 25/20/15/10/5/2.5/1.25kg plate; collars ignored.
The achievable range is 20–177.5kg in 2.5kg steps. A subset calculation produces
a real one-side plate recipe without reusing a plate. Competition: whole kilos,
20kg bar + 5kg collars; diagrams show a 2.5kg collar on the illustrated side.
Competition loading does not change Class / 1:1 / Solo session classification.

Suggested build-up: bar, then approximately 40/55/70/85% of the top work weight,
skipping duplicate rounded loads and anything at/above the first working set.
For opener rehearsal, build towards the opener, not the proposed third attempt.
Rest is zero through 50% of the chosen reference, then 45s through65%, 75s through80%,
and120s above80%. A block's duration can reduce these rests, down to30s above50%.
If the estimated work still exceeds the block, the preview says to allow more time
or reduce sets. Time estimates include a simple allowance for doing each set;
they are suggestions, not a prediction of personal lifting speed.

The exact percentages and rest tiers are app heuristics honoring the user's two-minute
cap. They are not a universal coaching standard. [Catalyst's competition guide](https://www.catalystathletics.com/article/1878/A-Simple-Guide-to-Weightlifting-Competition-Warm-ups/)
emphasizes adaptable timing. [Its training guidance](https://www.catalystathletics.org/about/train-heroic-faq/)
allows3–4minutes for the heaviest primary lifts. The timer never forces a next set.
Opener rehearsal does not model other athletes or predict platform times.

Train → Opener rehearsal accepts snatch/C&J openers and optional second/third
attempts, creates warm-ups, and logs as Solo using competition loading. Per-set
notes record how it felt. Keep-screen-awake is optional. A timestamp-based timer
recovers accurately after backgrounding; iPhone web apps cannot guarantee an
alarm or Live Activity on the lock screen.

## Data inventory and recovery

| Data | Storage and backup |
|---|---|
| Lift rows | Existing Log sheet; local cache + durable pending writes |
| Structured complexes | Full JSON in local lift-details metadata; appended Structure JSON / Workout ID columns with updated connector; readable component breakdown in Notes on older connector |
| Meet results / bodyweight | Existing Meets / Bodyweight sheets plus cached settings |
| Active draft, completed session history, templates | Local v3 keys + AppState snapshots with updated connector |
| Upcoming comp, attempt plans, goals, PB references, coefficients, athlete settings | Settings JSON + AppState snapshots |
| Older planner | `barbell_planner_v1` included in AppState snapshots |
| Pending changes | Durable local queue + snapshot for the connected sheet; restored queue preserves current pending writes |
| Sheet endpoint | Local connection setting and file backups; deliberately excluded from AppState payload |
| Device ID, update flags, diagnostics / cache | Local; caches are rebuilt, device has an independent cloud snapshot key |

AppState backups are append-only and chunked below Google Sheets' cell text limit.
Each device has its own key. A fresh GET must show the exact snapshot ID before
“confirmed” appears; opaque POST completion is insufficient. Unsupported connectors
show “plan backup needs connector update”. Backup / restore JSON file controls
remain available independently. No local clear/reset should be used before backup.

### One-time connector activation

Website publication does **not** deploy Apps Script. Existing lift sync remains
compatible. Plan backup and structured columns require deploying the updated
`barbell-log-apps-script.js`:

1. On a computer: spreadsheet → Extensions → Apps Script.
2. Copy updated connector from app Settings (also linked there), replace script,
   and save. A spreadsheet backup was made before this release's cleanup.
3. Deploy → Manage deployments → edit the **existing** web app → New version → Deploy.
4. Keep the existing `/exec` endpoint in Settings. Do not paste the Sheets URL.
5. Reopen the app; verify “Plan backup confirmed” in Settings and AppState rows.

No tool in the current session can activate the Apps Script deployment. Until
this is done, planning remains locally saved and downloadable as a file backup.

## Cleanup and UI changes

Six explicitly authorized dummy Log rows dated2026-10-30 were removed after a
workbook copy. A one-time client migration removes old test-day cache/pending
records and restores the known Lift Off Autumn2026 event, Nov8 at CrossFit Tufnell
Park. Blank session does not mean Competition. New training choices never include
Competition; actual competition entries can be edited preserving that explicit
session. Unspecified legacy hang maps above knee; ordinary blank full movements
are left alone. The builder offers no “Hang unspecified”; “Squat” hides “(Full)”.

Header logo, quiet refresh, automatic online/resume refresh, competition countdown
modal. Analytics filter by lift/variation/session/period; chart daily heaviest set,
training days, and volume only from known sets/reps. Mixed-variation views say so.

Phone geometry keeps navigation inside the reported viewport. Keyboard editing
keeps a stable app shell and scrolls the focused field into visible space. Native
installed-iPhone framing still requires an actual device check; desktop Chromium
safe-area simulations cannot verify iOS's installed status-bar metadata.

## Validation

`npm run check` covers pure loading, complexes, parsing, opener classification,
backend roundtrip/chunked backups, write readback, session badges, references and
phone geometry. `python3 scripts/training-browser-check.py` exercises real mobile
UI with a fake API; it never writes Google data. `iphone-layout-check.py` verifies
safe-area/keyboard constraints. Printed-image OCR was exercised separately with
the real CDN reader. Handwriting accuracy remains photo-dependent.
